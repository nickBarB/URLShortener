# Архитектура

[Описание и запуск](README.md)

Проект использует слоистую архитектуру. Исходники расположены в `src/main/java/`,
тесты — в `src/test/java/`. Точка входа `Main` собирает зависимости через конструкторы.

```text
controller → service → repository → repository.json → libs.json → JSON-файл
                ↓
              model
```

## Слои и компоненты

| Пакет | Ответственность |
|---|---|
| `controller` | Команды консоли, сессия и вывод результатов |
| `service` | Сценарии ссылок, пользователей и уведомлений; права доступа, TTL, лимиты и границы транзакций |
| `model` | Неизменяемые модели и их инварианты |
| `repository` | Интерфейсы хранения пользователей, ссылок и уведомлений |
| `repository.json` | Реализации репозиториев и общий снимок `JsonStorage` |
| `config` | Загрузка и проверка внешних настроек |
| `libs` | JSON-файлы, контракт транзакций, журнал, браузер и планировщик |

Сервисы работают с интерфейсами репозиториев и `libs.storage.TransactionManager`.
Файловые операции и Gson находятся в слое хранения. Компоненты `libs` не зависят
от моделей и сервисов приложения.

## Хранение данных

Путь задаётся параметром `storage.file`, по умолчанию — `data/shortener.json`.
Формат единого файла:

```json
{
  "version": 1,
  "users": [],
  "links": [],
  "notifications": []
}
```

Поля записей соответствуют Java-моделям. UUID и даты представлены строками;
время сохраняется с точностью до наносекунд. Пользователь существует независимо от ссылок.
Повреждённые данные, неизвестная версия, дубликаты и неизвестные владельцы отклоняются без перезаписи файла.

## Транзакции

`JsonStorage` объединяет операции репозиториев в общий снимок.
`JsonFileStore` получает блокировку, читает файл и после успешного изменения сохраняет
снимок через временный файл и атомарную замену. При ошибке снимок отбрасывается.
Вложенные операции используют текущую транзакцию; служебный `.lock` согласует доступ между процессами.

Создание пользователя и ссылки, переход со счётчиком и уведомлением, удаление по TTL
с уведомлением выполняются целиком. Чтение уведомлений удаляет их в той же транзакции.
Браузер открывается после сохранения; сбой вывода уведомления после сохранения может помешать его показу.

## Эксплуатация и проверка

Снимок читается и записывается целиком; хранение рассчитано на небольшие объёмы данных.
Файловая система должна поддерживать блокировки и атомарную замену.
JSON и `.lock` не изменяются вручную во время работы приложения.
Журнал записывается в `logs/`; консоль и фоновая очистка фиксируют непредвиденные ошибки.

Тесты используют временные JSON-файлы и проверяют сохранение между запусками,
конкурентные изменения, откаты, права доступа, TTL, лимиты и повреждённые данные.
Внешний браузер в тестах подменяется.
